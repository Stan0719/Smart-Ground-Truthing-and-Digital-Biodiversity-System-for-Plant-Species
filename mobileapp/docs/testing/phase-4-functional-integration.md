# Phase 4 functional integration (2026-11-22)

## Environment and evidence boundary

`plant-conservation-backend/test/mobile-api-routes-isolated.test.cjs` mounts actual `domain.cjs`, `plant-submissions.cjs`, `record-changes.cjs` and `observation-edits.cjs` handlers on loopback Express. Every test creates and closes its own in-memory PGlite database, using the backend schema and relevant existing migrations **only inside that disposable database**. Test users and QR/Plant/Species/Observation data are synthetic. The shared RBAC import is intercepted, and the session adapter is synthetic; this is functional route and SQL testing, not authentication or cybersecurity testing. No shared Supabase connection, production record or prohibited module was used.

| Workflow | Executed result | Important boundary |
|---|---|---|
| Add Plant | Real mobile `plantApi` called `POST /api/plant-submissions`; an approved synthetic Species and generated QR produced one Pending Review Plant, initial Observation, location, three photos, receipt and version row. Retry reused the receipt. Missing photos, >4 MiB photo, assigned/unknown QR were rejected; failed requests left no extra Plant. | Existing Species path only; pending/new Species registration paths not executed. Small generated JPEGs were used; no device camera. |
| QR lifecycle | `POST /api/qr-codes` generated unused codes. An unused code was retired through `DELETE /api/qr-codes/:id`; lookup returned the retired marker. `GET /api/qr/:token` returned the existing generated, Pending Review, Approved, Rejected and Withdrawn responses, and unknown codes returned 404. Reuse of assigned or retired QR failed. | Approved/rejected/withdrawn states were set in **disposable test data**, not through an Officer route. Generated QR printing and camera scanning not tested. |
| Plant correction | A synthetic Correction Required review and version were seeded; `PATCH /api/my-plants/:id` resubmitted changed notes, retained three photo IDs and created a new Pending Review history row. | Officer decision itself was not tested. |
| Species correction | A synthetic Correction Required request was seeded; `PATCH /api/my-species-requests/:id` changed description, retained the photo, incremented content revision/review cycle and added a Pending Review version. Feedback was retrieved by the detail route. | Officer decision itself was not tested. Under the tested legacy migration set, the prior version retained `Correction Required` status. |
| Approved Plant edit | After seeding an approved state, `POST /api/record-changes` created a Pending Review proposal/version; approved Observation content remained unchanged. | No Officer approval of the proposal or edit-correction resubmission was exercised. |
| Approved Species edit | After seeding an approved request and Species, `POST /api/record-changes` created a Pending Review proposal/version; approved request text remained unchanged. | No Officer approval of the proposal or edit-correction resubmission was exercised. |
| Observation edit and correction | `POST /api/observation-edits` created an edit, owner retrieval worked, a second Botanist's read failed, and retry reused the request. After a synthetic Correction Required decision, `PATCH /api/observation-edits/:id` submitted revision 2 and an event while the approved Observation content remained unchanged. Feedback was retrieved. | Migration 021 legacy edit path was tested; newer Observation submission-version migration 029/030 path was not. |
| Mobile API reliability | Real mobile `plantApi` mapped connection failure, timeout and non-JSON response to expected error codes. A caller retry succeeded; `plantApi` made no hidden duplicate retry. The supplied body object remained unchanged after failure. | The timeout was injected, not measured using a real slow network. This does not prove screen-level form state retention. |
| Local drafts and photos | Five existing focused mobile test files passed **56/56** cases, including recovery, owner isolation, autosave, photos/QR/GPS, failure preservation and restored oversized-photo validation. | Mocked/local automated tests, not a phone restart, camera or offline cloud synchronization trial. |

## Remaining functional gaps

- Successful Officer review/approval and resulting public gallery/version transition were not run. This phase seeded review states directly in disposable data only to exercise Botanist correction routes.
- Approved Plant/Species edit **correction resubmission** requires the immutable version-revision migration 028 and more complete review fixtures; it was not run. Original Plant/Species corrections were run.
- Observation edit was tested against migration 021 without the newer versioning migrations 029/030. Newer immutable version and photo evidence paths remain unverified.
- New/pending Species within Add Plant, full QR printing/camera scanning, native file capture, phone offline recovery, notification delivery, and real network timeouts remain unverified.
- The production authentication provider and role policy were intentionally excluded from this phase. Physical-device and UAT work remain pending.
