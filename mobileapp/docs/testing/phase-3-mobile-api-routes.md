# Phase 3 mobile API route audit (2026-11-22)

This inventory covers only backend and mobile files in the authorized scope. Route handlers below are real implementation routes. Phase 3 mounted a subset over loopback with an in-memory PGlite database and synthetic sessions. The session and policy substitutes are functional test infrastructure; they do not establish deployed grants or login behavior. Standalone Phase 3 cybersecurity assertions were later removed from the mixed test as outside this contributor's individual scope.

The route harness retains `identity` and `requirePermission` as dependencies, with synthetic session and policy fixtures. Phase 3 historically checked invalid/missing/unknown bearer tokens, but those standalone cybersecurity assertions were removed from the current individual functional test. The normal `server.js` startup imports an authentication provider outside the authorized directories; that startup path was not invoked. The fixture intercepts the out-of-scope policy import before resolution and does not load that file. No production middleware was changed.

The test-only database is created by `test/mobile-postgres-fixture.cjs`, uses no connection string or environment credentials, and is closed after every test. Backend migrations 004, 006, 008, 011 and 014 were applied only to disposable in-memory instances as needed; no migration file or shared schema was modified. One test transpiles the actual `mobileapp/utils/plantApi.js` client and sends requests to mounted routes. It substitutes only the mobile SecureStore session and base URL. These are frontend-to-backend integration tests, not physical-device or complete production end-to-end tests.
